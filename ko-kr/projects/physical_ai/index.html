현대로템 산학협력

4족 보행 로봇 기반 음성·텍스트 제어 점검 시스템

2026년 8월 – 진행 중

ROS 2 SLAM Nav2 LiDAR Python

프로젝트 개요

과제
사람이 접근하기 어려운 공간에서 4족 보행 로봇이 지정 지점으로 이동해 점검 사진을 촬영하는 시스템 개발. 네트워크 연결이 불가한 환경을 전제로, 작업자는 모바일 앱의 음성·텍스트로 지시합니다.
수행
SLAM 기반 맵 작성·위치 추정·지점 등록·자율주행·도착 처리의 지점 주행 파이프라인을 ROS 2 Foxy 환경에 직접 구현했습니다.
결과
실내 시험 공간에서 지점 주행 8회 전부 도착, 시작 위치 초기화 오차 1 cm·0.3°(기준 10 cm·5°). 현재 비전 기반 구도 보정과 사진 품질 검증 단계로 진행 중입니다.
기간
2026년 8월 – 진행 중
팀
연세대 ANDLab · SLAM·자율주행 담당, 고객사 주 연락 창구
기술
Unitree Go2 EDU (Jetson Orin NX), Hesai XT16 LiDAR, ROS 2 Foxy, Nav2, AMCL, Python

배경

현대로템은 철도 차량 점검 중 사람이 접근하기 어려운 구역의 사진 촬영을 4족 보행 로봇으로 대체하는 기술을 검토하고 있습니다. 작업자가 모바일로 “A 위치로 가서 사진 찍어”와 같이 지시하면, 로봇이 해당 지점으로 이동해 촬영하고 결과를 돌려주는 구조입니다.

  • 제약. 네트워크 연결 불가 환경 기준. 보안상 현장 자료 공유와 현장 방문이 불가해, 연구실 내 실내 시험 공간을 기준으로 개발합니다.
  • 우선순위. 6개월 내 “음성·텍스트 명령 → 이동 → 촬영 → 결과 확인” 전체 흐름을 우선 완성하고, 이후 촬영 위치·구도 고도화를 진행합니다.

내 역할

  • SLAM·자율주행 파트 담당: 맵 작성, 위치 추정, 지점 등록, 지점 주행, 도착 처리 구현
  • Go2 주행 특성 실측 및 속도 보정, 현장 시험 기반 주행 문제 해결
  • 연구실 측 고객사 주 연락 창구 (요구사항 질의 정리, 정기 회의 자료·회의록 송부)

접근 방법

  1. 맵 작성. 추가 장착한 XT16 LiDAR로 시험 공간의 맵을 작성하고, 기준 위치를 원점으로 지정했습니다.
  2. 위치 추정 및 지점 등록. AMCL 기반으로 로봇 위치를 추정하고, 촬영 지점을 ID·이름과 함께 맵에 저장했습니다.
  3. 지점 자율주행. Nav2로 경로를 계획하고, 실제 이동 명령은 브리지를 통해서만 로봇에 전달되도록 구성했습니다.
  4. 도착 처리. 방향 오차가 3°를 넘으면 끊어 돌기로 보정(최대 4회)하고 자세를 교정한 뒤, 도착이 확정된 경우에만 자동 촬영합니다.
  5. 검증. 실제 로봇 없이 단계별 동작을 확인하는 자동 테스트와 실제 로봇 주행 시험을 병행했습니다.

결과

1 cm · 0.3° 시작 위치 초기화 오차 (기준 10 cm · 5°)
8 / 8 저장 지점 주행 도착 (지점 5개 등록)
176개 자동 테스트 통과

시작 위치 초기화부터 지점 등록, 자율주행, 도착 후 자동 촬영까지 지점 주행 흐름 전체를 실제 로봇에서 확인했습니다. 팀 단위로는 비상정지 음성 인식(「정지」·「그만」, 오탐률 3.4%), 소형 명령 해석 모델(HyperCLOVAX 0.5B, 351 MiB), 텍스트 명령 기반 주행·촬영이 함께 구현되어, 앱 텍스트 명령으로 지점 이동과 촬영까지 수행하는 단계에 도달했습니다.

트러블슈팅

1. 로봇 컴퓨터의 SLAM 패키지 부재

문제. 로봇 컴퓨터(Jetson)에 SLAM·스캔 변환 패키지가 설치되어 있지 않았고, XT16 제조사 SLAM은 라이선스 인증 검사로 사용할 수 없었습니다.

원인. 로봇의 ROS 2 버전이 Foxy로, 최신 오픈소스 패키지를 그대로 설치할 수 없는 환경이었습니다.

해결. 최신 오픈소스를 참고해 필요한 기능을 Foxy에 맞는 Python 노드로 직접 구현했습니다.

결과. 맵 작성부터 도착 처리까지 지점 주행 흐름 전체를 로봇에서 실행했습니다.

2. 목표 지점 주변 맴돌기와 조기 정지

문제. 목표 주변에서 약 25초간 맴도는 현상과, 목표 1.4 m 앞에서 멈추는 현상이 발생했습니다.

원인. Nav2의 방향 정렬 동작이 Go2의 회전 특성과 맞지 않았고, 전체 경로 계획에 실시간 스캔을 포함해 반사 하나에도 경로가 막혔습니다.

해결. 방향 정렬을 Nav2에서 브리지로 옮기고, 전체 경로 계획에서 실시간 스캔을 제외했으며, 자동 복구 동작을 비활성화했습니다.

결과. 저장 지점 주행 8회 전부 도착했습니다.

3. 저속 명령의 미반영

문제. 0.2 m/s 이동 명령에 실제 속도가 약 0.06 m/s에 그쳤고, 저속 회전 명령도 제대로 반영되지 않았습니다.

원인. Go2는 일정 속도 이하의 명령에서 실제 움직임이 크게 줄어드는 특성이 있었습니다.

해결. 실측 결과를 바탕으로 0.05~0.25 m/s 명령은 0.25 m/s로, 0.6 rad/s 미만 회전은 0.6 rad/s로 상향하고, 최대 속도를 0.4 m/s·0.8 rad/s로 제한했습니다.

결과. 저속 구간의 정지·지연 없이 지점 간 주행이 가능해졌습니다.

4. LiDAR 처리의 CPU 과부하

문제. LiDAR 처리 노드의 CPU 사용률이 480%에 달했습니다.

원인. 처리 스레드 수 제한이 없어 Jetson 자원을 과점유했습니다.

해결. 처리 스레드 수를 제한했습니다.

현재 진행 및 향후 과제

  • 반복 도착 정밀도(목표 10 cm·3°), 정지 방법별 정지 시간 등 정량 검증은 진행 중입니다.
  • 고객사 요청에 따라 표식(AprilTag) 없는 비전 기반 구도 보정, 사진 품질 검증 로직, 환경 변화 대응을 검토하고 있습니다.
  • 모든 시험은 실내 시험 공간 기준으로, 실제 점검 환경 적용을 위해서는 현장 조건에서의 재검증이 필요합니다.
